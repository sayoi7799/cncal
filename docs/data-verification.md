# 节假日数据核对记录

`data/holidays.json` 的初始数据由 chinese-days@1.5.9 导入(见 `scripts/import_holidays.py`)。
差分测试证明的是:本项目的加载、展开、校验与判定逻辑与 chinese-days 的结果一致;
它**不能**证明数据本身与国务院通知一致。所以对最近三年,以及出处不是一手来源的最早两年,
对照通知原文做了人工核对。

## 说明

- **节日名称与区间的划分是数据的组织方式,不是通知的内容。** 例如 2025 年国庆与中秋合并放假 10/1–8,
  通知里是一个 8 天的假期;数据里按 chinese-days 的做法把 10/6 记为「中秋」、其余记为「国庆节」,
  放假的日期集合与通知完全一致。
- 2005 年没有找到政府网站上的通知全文,采用的是法律数据库转载的全文,比 chinese-days 原来引用的
  百度知道可靠,但仍不是一手来源。2004 年采用了陕西省人民政府网站转发的通知全文。
  两处出处在 `scripts/import_holidays.py` 的 `SOURCE_OVERRIDES` 中记录。
- 提取通知内容时,网页读取工具会对页面做摘要,所以上表里的日期是摘要结果,而不是对原文的逐字比对。
  需要更严格的核对时,应当直接对照页面原文。

## 已知限制

- 其余年份(2006–2023)的数据没有逐年对照原文,以 chinese-days 的数据为准。
- 次年的通知常常调整上一年最后几天的安排;最新覆盖年份(2026)的年末几天,在 2027 年的通知发布后
  可能变化(设计文档 §9 风险 2)。
